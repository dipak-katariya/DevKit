Phase 3: improvement strategy, and the plan in progress

You approved fast-tracking the "act now" fixes, removing Merge Tool and all local-git code, resolving the three Phase 2 risks and implementing the three top opportunities. This page records the strategy those changes follow, the task plan, what is deliberately left out, and what still needs your decision.

Approved: implementation under way

Your decisions this round

  • Fast-track the exposure fixes ahead of the full safety net. Each still gets tests pinning today's behaviour first, and its own commit.
  • Remove Merge Tool entirely, together with every piece of code that runs git.exe on your machine: the cherry-pick service, the local-clone scan and mapping in Settings, and their settings keys. Git features will be designed again in a later phase. Features that use TFS's own Git API over REST stay: Code Merging Sheet, Branch Creator, Branch Delete.
  • Resolve the three Phase 2 risks: wrong data written to shared systems; PAT exposure and settings loss; organisation-specific values blocking an open-source release.
  • Implement the three top opportunities: one shared TFS transport, tests and a CI gate before fixes, and a per-user secure settings store with organisation values moved out of code.

Root-cause themes

Five causes behind most of the 84 findings and 119 confirmed or plausible bugs. Each has a measurable target.

1

A trust model that does not match the machine

DevKit assumes one person on a private machine. It actually runs on a shared Remote Desktop server, with no login, the PAT in the page, and settings in a folder other users can modify.

Explains
B001, B002, SEC-01, SEC-02, SEC-12, B110, B113, B114, B116, B112, ARC-12
Direction
Loopback only plus a per-user session cookie obtained through a one-time launch link. Host and Origin checks. The PAT never sent to the browser. Settings in an owner-only per-user folder, written atomically with a backup, and the PAT encrypted with the server URL as extra DPAPI entropy.
Trade-off
Opening DevKit now needs its launch link once per browser profile. The settings file moves, with an automatic one-time migration.
Done when
A request without the session cookie gets 401; a foreign Host gets 400; /settings HTML contains no PAT; killing a save leaves a readable file or a recoverable backup; tests prove each.
2

No safety net and no quality gate

Every TFS, git and settings write was at 0% coverage. The test project isn't in the solution, and there is no CI or analyzer, so nothing stops regressions.

Explains
TST-01 to TST-04, TST-15, TST-17, DX-01 to DX-03, MET-01 to MET-06
Direction
Characterization tests with recording fakes before each change. One solution that builds and tests everything. A Windows CI job: build with warnings as errors, test with coverage, a guard against company names and committed settings files. SonarAnalyzer reports on every build, and rules are tightened by ratchet.
Trade-off
Sonar starts non-blocking: making all of its rules blocking at once would mean hundreds of unrelated edits.
Done when
Every write path has a test; changed code is at 80% line coverage or more; CI is green on the branch.
3

No shared TFS transport, and failures that look like success

Four services each build their own request client. Each call site decides on its own about throttling, cancellation, paging, errors and logging, and many catch-all blocks turn failures into empty results.

Explains
ARC-05, ARC-06, ARC-07, ARC-10, CQ-05, CQ-06, CQ-12, DX-05, SEC-11, B030, B033, B051, B075, B103, B104
Direction
One DI-registered transport with a delegating handler for the shared gate, timeouts, structured request logging (never the PAT) and consistent error text. Cancellation is passed through, failures are reported, and the UI shows TfsErrors.Describe instead of raw exception text.
Trade-off
Touches every service; done behind the write-payload characterization tests so request shapes stay identical.
Done when
Zero call sites create their own client; zero ungated requests; zero raw ex.Message in the UI; payload tests unchanged.
4

Logic and state inside pages, copied between pages

Six pages each copy the shared metadata loader, and the copies have drifted (B074). Badge rules, area/sprint rules and click-outside handling are copied too. Verification state has several writers and no run id.

Explains
ARC-04, ARC-09, ARC-13, ARC-14, CQ-01 to CQ-04, B036, B037, B040, B074, B078
Direction
Move shared plumbing into named services and components: one metadata loader, one set of badge rules, one click-outside lifecycle. Give verification writes a bundle generation so a stale run cannot overwrite a newer one.
Trade-off
Some badge colours change where the copies had drifted; one rule set wins.
Done when
One copy of each; the B036, B037 and B040 tests pass with the fixed behaviour.
5

Built for one organisation

Company names, a custom TFS field, team areas and a repository-specific branch are hard-coded. Fixtures use real names, and there is no LICENSE.

Explains
ARC-23, SEC-10
Direction
An Organization section in settings: hidden areas, the task execution-type field, revised-estimate fields. Your own settings keep today's values, and the code ships neutral defaults. Neutral test fixtures, and a CI guard so the names cannot come back.
Trade-off
Until your settings hold the organisation values, task creation would stop setting the custom field and hidden areas would reappear. Your own settings are filled before you switch over.
Done when
Zero tracked lines contain the company name or internal host; behaviour on your server unchanged.

Target architecture

One folder per feature, plus shared code named after what it does. Shared code is extracted only where two or more features use it. This round puts new shared code where it belongs; moving the existing files into this layout is a separate, move-only change (not this round).

What we are not fixing now, and why

  • Moving every file into the folder layout above. It is pure churn while behaviour is changing; it follows as a move-only commit once these fixes are in.
  • Splitting all 109 extra public types into their own files. It conflicts with your rule against small fragment files (Q2, still open). Applied only where a file is being changed anyway.
  • bUnit component tests. They need a new package download. Decision logic is moved into services instead, where plain unit tests reach it.
  • Rewriting git history and choosing a LICENSE. Both are your call: a history rewrite changes every commit id and needs a force-push; the licence is a legal choice.
  • The meaning of "Merged" (B028, B056) and the by-design items B024 and B125. These need your decision; behaviour stays as it is until then.
  • Generalising the Task Creation catalog (task names, execution types). It is your delivery process rather than a company name; scope question still open.
  • The Sonar warning backlog beyond the touched files, and low-severity cosmetic bugs (for example B083 sidebar on narrow screens, B086 focus target, B098 SVG culture). Logged in the Phase 2 report, scheduled after this round.
  • The hosted multi-user login in docs/analysis/hosted-login-analysis.md. A separate track; this round only secures the local mode.

Rollback
